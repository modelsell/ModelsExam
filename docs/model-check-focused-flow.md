## 报告与评分

主视图只保留三块摘要和一张基线对照表：

1. **模型身份线索**：优先展示声明型号冲突；同时展示 6 道核心能力题的答对率和可评分覆盖数。该分数不是模型真实性分数。
2. **性能指标**：固定 3 次采样的首个可见文本延迟中位数、全程输出速率；展示满足多少条可比较基线的性能标准。
3. **基线相似度**：显示两类指纹完整可比时最高的相对相似度。相差不到 5 分的类型并列，既有规则只作相对展示，未经准确率校准，不能作为身份概率或真伪阈值。

基线表逐条列出：类型/型号、字母与动物相似度及样本缺口、共同能力题的本次/基线得分和不同答题项、性能得分和本次值/阈值。不同类型、不同基线不混成一个性能分数。

指纹沿用 Jensen–Shannon 分布相似度。每类双方至少各 10 个有效样本、题目及实际参数 profile 相同才计分。v2 的字母/动物题与 v1 对应原题相同，因此可按类别比较。只满足一类时显示部分得分，但不参与最高相似类型选择。没有证据显示“未评分”，不显示“失败”。

性能默认容差 25%，可在测试前设置 0–100%，随本次报告保存：

- 本次首字延迟中位数 ≤ 基线中位数 × (1 + 容差)，50 分；
- 本次输出速率中位数 ≥ 基线中位数 ÷ (1 + 容差)，50 分。

只有 3 对有效、同题同参数性能请求才产生 0/50/100 分。不完整时保留数值和缺口，不推断达标。有效采样要求输入输出协议有效、返回输出计数至少 64、有至少两个文本事件和有效首字时间。输出速率 = **返回的 output_tokens / 整个请求耗时**，不等于纯解码速率，也不能校验 token 上报真实性。网络和负载会影响结果；3 次只是小规模运行检查。

提示词/缓存 token 对账、详细题目与分布、全部请求证据收进可展开区域。历史和实时过程使用同一套报告组件。历史列表展示与报告五维均分相同的“报告分数”，不使用旧的通过率作为总分，也不将分数解释为身份认证。

## 证据边界与历史兼容

型号字段可以被代理改写；确定性小题与少量分布采样可提示替换或行为差异，不能证明后端实际模型身份。完整的验证仍需可信直连对照或提供方的调用记录。基线类型均由操作者命名，不代表官方认证。

历史按共同题目和 25% 容差渲染新的对照视图；原始检测证据、基线 snapshot_json 和历史版本保持不变。新报告保存精简选项、性能容差、版本化测试数据与当次引用快照。

## 报告备注与历史分数

报告顶部直接展示名称，不带“备注”前缀，检测结束后通过“编辑”可修改或清空，最多 200 个字符。备注随报告保存，刷新、历史列表、HTML/JSON 导出使用同一个值；未设置备注的旧报告沿用原渠道名称，明确清空后不再回退。修改备注不修改系统渠道名称或当次基线快照。

`PATCH /api/model_check/history/:id/remark` 接收 `{ "remark": "..." }`，权限与检测历史一致且只能修改本人记录。仍在运行的检测返回 409。存储更新只涉及独立备注字段及报告 JSON 的 `remark`，保留其他已知和未知证据字段。

历史记录新增 `remark`、可空 `score` 和内部 `score_version` 字段，通过跨数据库迁移补齐。每次检测保存时同步计算与报告相同的五维均分；列表不读取已计算记录的完整报告。旧记录按当前页补算并缓存，遇到并发补算会回读已落库结果。零分显示 `0/100`，未评分显示 `—`，运行中分数标注为阶段分。前后端通过同一组版本化测试用例校验评分一致性。

协议参考：[Claude token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting)、[Claude prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[AWS prompt caching](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)。同一渠道计数接口和 usage 对账只提供一致性线索，并非独立的无注入证明。
