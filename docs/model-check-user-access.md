# 模型检测用户入口

“模型检测”和“模型能力”是两个独立主页，公共导航分别链接到 `/model-check` 和 `/model-capabilities`。检测首页中央显示 Base URL、API Key 和模型选择表单，下方直接显示“我的检测”列表；基线及检测范围收进默认折叠的“高级设置”。模型选择支持搜索平台 Claude 目录和手动输入自定义名称，目录建议不代表所填接口的模型授权。

模型能力页保留原有图表、章节锚点和 `modelCapabilities` 导航配置；检测页独立使用 `modelCheck`，二者的排序、显隐及登录要求可分别配置。旧配置自动补入检测入口；旧配置未指定检测入口顺序时，新增入口放在模型能力旁边。旧的 `/model-check?view=capabilities` 链接跳转到 `/model-capabilities` 并保留锚点，两页拥有独立标题、规范链接及站点地图条目。

访客可以浏览模型能力；登录后，普通用户、管理员及工作区子账号均可填写自己的 Base URL、API Key 和模型名称，运行现有 Claude / Anthropic 兼容检测。检测请求由所填 API 服务商计费。现有套件的范围和评分保持不变，包括能力题、性能、缓存、Usage Token 完整性、提示词检查，以及可选视觉、PDF、Bedrock 诊断。这里不提供尚未实现的通用 OpenAI 或 Gemini 检测。

## 主页布局

- 顶部沿用公共导航，检测主页内部导航仅提供开始检测和历史记录锚点。
- 首屏使用双行主题标题、兼容协议说明和居中连接面板，下方以简短说明展示能力与协议、性能与缓存、报告导出。
- 历史记录作为独立页面区块，包含未登录和无记录的引导状态；底部模型能力入口跳转到独立能力页，不再切换内嵌页签。
- 全部使用现有主题色和组件，兼容明暗主题与移动端。高级选项、检测运行、报告抽屉及导出逻辑保持不变。

## 记录及导出

- 检测开始后自动保存当前用户的记录，继续保留中断、取消和失败的证据。
- “我的检测”支持模型、状态筛选和分页。可以直接导出 JSON，或在侧边抽屉打开完整报告，下载 HTML、打印及保存 PDF；进行中的检测也在抽屉内展示进度和结果。
- 检测详情、备注修改、基线列表、创建及选择基线均按认证用户 ID 隔离。请求参数不能指定其他用户作为归属人。
- 浏览器缓存的历史及基线包含用户 ID，切换账号不会复用另一账户的检测数据。
- HTML/JSON 沿用既有报告生成、评分和密钥脱敏规则。

## 权限边界

`/api/model_check`、历史、备注及基线接口使用 `UserAuth`。`/api/channel/:id/claude_check` 仍要求管理员及 `ChannelOperate` 权限；普通用户无法通过渠道 ID 使用系统渠道凭据。

普通用户提交的地址强制启用私有/保留地址拦截及域名 IP 校验，不受管理员关闭通用 SSRF 防护的影响。检测连接直接使用已验证地址，禁止通过环境代理重新解析 DNS，并拒绝重定向。保留现有每账户并发控制、全局检测并发上限、请求预算和整轮超时。

## 本地验证

- 路由测试覆盖普通账户及工作区子账号访问、未登录拒绝、跨账户记录/备注/基线拒绝，以及系统渠道权限不变。
- 网络测试覆盖 SSRF 开关关闭、内网访问被允许、域名 IP 校验关闭等设置下的普通用户地址限制。
- 前端测试覆盖账号切换后的基线缓存、用户导航，以及现有报告、导出、评分和流式状态回归。
